# fx_sim — 仮想100万円 FX（主要JPYクロス）自動運用シミュレーション・検証基盤

実際の値動き（yfinance / JPY建て日足）を使い、**架空の100万円**で自動売買ロジックを
検証する。実売買・送金は一切行わない。投資助言でもない。

[crypto_sim](../crypto_sim/) の設計をFX（USD/JPY・EUR/JPY・GBP/JPY・AUD/JPY）に
応用したもの。**今回の範囲はバックテスト・パラメータ感度までの「検証基盤」だけ**
（データ取得・執行モデル・戦略・レジーム判定・バックテスト・自動テスト・
パラメータ感度）。crypto_sim にある `live_trade.py`（リアルタイム運用）・
`dashboard.py`（ブラウザ表示）・GitHub Actions（自動実行）はまだ無い。
パラメータの妥当性を確認できてから、必要であれば追加する。

ローカルのgitリポジトリとして管理している（`日経Sim` フォルダ直下、
crypto_sim とは独立した別プロジェクト）。リモートは無い。

## crypto_sim からの主な変更点

暗号資産とFXでは前提が違う部分があり、そのままコードを転用すると
静かに間違った結果になる。変更した箇所とその理由:

| 項目 | crypto_sim（暗号資産） | fx_sim（FX） | 理由 |
|---|---|---|---|
| ユニバース | BTC/ETH/XRP/SOL の4銘柄 | USD/EUR/GBP/AUD の対JPY4ペア | 「上昇銘柄比率」という指標を成立させるには複数銘柄が要る（USD/JPY単体では母数1で意味を成さない） |
| 年間の観測本数 | 365（年中無休） | 261（実測。土日休場） | `metrics.py` のボラ・Sharpe年率換算に使う定数。混同すると約1.18倍過大に出る |
| 日足欠損の判定 | 抜け＝すべて異常 | 平日の抜けだけ異常、土日は正常 | FXは土日休場が前提。`data.find_gaps()` を参照 |
| コスト前提 | 手数料0.15%+スリッページ0.10% | スプレッド相当0.01%（FEE=0） | 国内FX会社の多くは別建て手数料が無くスプレッドのみ。暗号資産よりコストは1桁以上軽い（要検証・概算） |
| レジームのボラ閾値(HIGH_VOL) | 90%（年率） | 15%（初期値） | FXは暗号資産よりボラが1桁小さい（USD/JPY 30日年率ボラ実測: 中央値9.2%・90%点14.5%）。90%のままだと常に「落ち着いている」判定になり指標が機能しない |
| レバレッジ・証拠金・スワップ | 該当なし（現物のみ） | 未対応（現物のみのまま） | FXの本来の姿（レバレッジ・スワップ）を省略した簡略版。「既知の限界」参照 |

`TREND_MA`（200日線）・`BREADTH_MIN`（50%）・`ATR_MULT`（3倍）・`MAX_WEIGHT`（30%）・
`COOLDOWN_DAYS`（10日）は crypto_sim の値をひとまず出発点として使っている
**未検証の初期値**。下記「パラメータ感度」の節を参照。

## 構成

| ファイル | 役割 |
|---|---|
| `data.py` | 価格取得＋CSVキャッシュ（JPYクロス4本）。土日休場を織り込んだ欠損判定 |
| `broker.py` | 現金・ポジション・コスト・目標ウェイトのリバランス |
| `strategies/base.py` | 戦略の基底 + Context + 指標(ATR/RSI)。銘柄非依存で crypto_sim と同一 |
| `strategies/baselines.py` | USD/JPY買い持ち / 均等分散 / 分割投入 — ベンチマーク |
| `strategies/trend.py` | ドンチャン+ATRトレーリングストップ、移動平均クロス |
| `strategies/rotation.py` | モメンタム・ローテーション、RSI逆張り |
| `strategies/regime_switch.py` | レジーム切替戦略（実運用候補の本命） |
| `regime.py` | 相場付きの判定（200日線・ボラ・上昇銘柄比率の3つだけ） |
| `metrics.py` | CAGR / 最大DD / Sharpe / Sortino / Calmar / 勝率 / PF |
| `backtest.py` | 過去検証エンジン。翌日始値で執行し、結果を `results/` に出力 |
| `sensitivity.py` | パラメータ感度の検査（`--check` でCI的な崖検出も可能） |
| `test_all.py` | 不変条件のテスト（17件） |

## 前提条件

- **ユニバース**: USD/JPY・EUR/JPY・GBP/JPY・AUD/JPY（JPY建て直接なので為替換算不要）
- **時間軸**: 日足
- **コスト**: スプレッド相当0.01%（要検証・概算。上表参照）
- **現物のみ**（レバレッジ・証拠金・スワップなし）
- **執行**: i日目の**終値まで**を見て決めた注文を、**i+1日目の始値**で約定
  （look-ahead bias 対策。crypto_sim と同じ）

## 使い方

```bash
pip install -r requirements.txt
python data.py                              # 価格データを取得してキャッシュ
python backtest.py                          # 全期間で全戦略を比較
python backtest.py --split                  # 検証用(2018-2022)と検証外(2023-)を分けて比較
python sensitivity.py                       # パラメータ感度の一覧表示
python sensitivity.py --check               # 崖検出だけ行う（終了コードで判定）
python test_all.py                          # 不変条件のテスト
```

## 検証結果（初回・2026-08時点）

`python backtest.py --split` の実測（USD/EUR/GBP/AUD対JPY、コスト込み）。

| 戦略 | 2018-2022 総リターン / 最大DD / Calmar | 2023-2026 総リターン / 最大DD / Calmar |
|---|---|---|
| USD/JPY買い持ち | +18.5% / -12.2% / 0.28 | +21.7% / -12.9% / 0.43 |
| 均等分散(月次) | +8.0% / -16.3% / 0.09 | **+30.3%** / -12.2% / 0.62 |
| 分割投入(12ヶ月) | -0.3% / -6.0% / -0.01 | +13.7% / -12.9% / 0.28 |
| ドンチャン20/10 | +6.1% / -6.8% / 0.17 | +15.1% / -6.2% / 0.63 |
| ドンチャン55/20 | -1.6% / -9.5% / -0.03 | +11.9% / -5.4% / 0.58 |
| 移動平均20/60 | +5.6% / -15.3% / 0.07 | +20.6% / -13.1% / 0.40 |
| 移動平均5/25 | -2.3% / -16.2% / -0.03 | +20.0% / -7.6% / **0.68** |
| モメンタム上位2 | +9.4% / -15.7% / 0.12 | +18.5% / -14.6% / 0.33 |
| RSI逆張り | **+15.5%** / -7.5% / **0.39** | +5.2% / -7.6% / 0.19 |
| レジーム切替 | +2.4% / -7.1% / 0.07 | +5.6% / -6.9% / 0.22 |

**crypto_sim とは違い、レジーム切替戦略が両期間ともベンチマーク（買い持ち・均等分散）に
Calmarで負けている。** これは想定内で、理由は上表の「初期値」節の通り、
HIGH_VOL をはじめとするパラメータがFXデータでまだ検証されていないため。
crypto_sim のレジーム切替が強かったのは、この作り込みを実際にやったからであり
（README「実運用戦略（レジーム切替）の検証」参照）、fx_sim はまだその手前の段階。

参考までに、単純なトレンドフォロー（ドンチャン20/10・移動平均5/25）は
2023-2026でCalmar 0.6台と悪くない。RSI逆張りは2018-2022で相対的に良く、
「暗号資産の強いトレンド相場では弱い」という crypto_sim の想定とは
様子が違う可能性がある（FXはレンジ相場の比率が暗号資産より高いため、と
考えられるが、これも今後の検証課題）。

### パラメータ感度（`python sensitivity.py`）

4パラメータとも、値を1つずつ動かした結果は滑らかで、特定の値でだけ跳ねる
「崖」は無かった（`sensitivity.py --check` も異常なしで通過）。

- 大局トレンドの移動平均: 100〜300日でCalmar -0.05〜0.17（IS）/ 0.20〜0.33（OOS）、崖なし
- ボラ閾値（HIGH_VOL）: **0.08〜0.25の範囲で結果が完全に同一。この閾値は現状の
  検証期間・戦略構成では実質的に何も判定していない**（後述）
- ATRストップ幅: 2.0〜4.0倍でCalmar -0.04〜0.09（IS）/ 0.19〜0.23（OOS）、崖なし
- 1銘柄上限: 0.5以上は結果が変わらない（crypto_simと同じ傾向）。0.3〜0.8で
  Calmar 0.07〜0.11（IS）/ 0.19〜0.22（OOS）、崖なし

**崖が無いこと自体は良い兆候（少なくとも偶然に当てにいった形跡はない）だが、
Calmarの絶対水準がベンチマーク（USD/JPY買い持ち0.28/0.43、均等分散0.09/0.62）を
一貫して下回っている。** 特にボラ閾値が無反応なのは、`above`（200日線比較）
だけで「弱気」が決まってしまい、ボラ・上昇銘柄比率の出番がこの検証期間では
ほとんど無かった可能性を示唆している——4銘柄がJPYクロスで相関が高く、
「上昇銘柄比率」がcrypto_simほど独立した情報を持っていないのかもしれない。
これは**パラメータの微調整ではなく、レジーム判定の構造自体を見直す必要がある**
ことを示す結果で、次にやるべきことは閾値探しではなくこの一致率の分析。

## 既知の限界（今後の課題）

- **レバレッジ・証拠金・ロスカットを未実装。** 現物のみのモデルなので、
  実際のFX運用（多くはレバレッジあり）とは資金効率がまったく違う
- **スワップポイント（金利差調整）を未実装。** 特にAUD/JPY・GBP/JPYは
  無視できない額になりうる。ロング・ショートの持ち越しコストを反映していない
- **コスト前提が概算。** スプレッド0.01%は通貨ペア・時間帯・ブローカーで
  変わる実際の値ではなく、大まかな見積もり
- **レジームのパラメータが未検証。** crypto_simの値を出発点にしているだけで、
  上記の検証結果が示す通り、現状ではベンチマークに勝てていない
- **live_trade.py・dashboard.py・GitHub Actions相当が無い。** 今回は
  検証基盤までの範囲。パラメータの目処が立ってから追加を検討する

## 過剰最適化を防ぐためのルール（crypto_simと共通）

- 作り込みは 2018-2022 の期間だけで行う。2023- は検証にしか使わない
- パラメータを1つずらして崩れる結果は偶然とみなす
- コストを外した数字は見ない
- 取引回数が極端に多い戦略は、コストを上げて再確認する
